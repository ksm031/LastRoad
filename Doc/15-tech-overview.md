## Pseudo 3D 구현 핵심 로직

```
# Godot 2D 기반 Pseudo 3D 오브젝트 배치
# z_value: 0.0 (소실점) ~ 1.0 (화면 하단)
func update_sprite_transform(z_value: float):
    var scale_factor = lerp(0.05, 1.0, z_value)
    var y_pos = lerp(HORIZON_Y, SCREEN_BOTTOM, z_value)
    var x_pos = lerp(center_x, lane_x, z_value)  # 커브 적용
    
    sprite.scale = Vector2(scale_factor, scale_factor)
    sprite.position = Vector2(x_pos, y_pos)
```

## 도로 렌더링 시스템

### 레이어 구조

```
레이어 3  │  오브젝트 (컬트, 폐차, 나무 등) — 빌보드
레이어 2  │  차선 (황색 점선, 흰색 실선)   — 아스팔트와 동일 속도
레이어 1  │  아스팔트 배리에이션 타일       — 스크롤
레이어 0  │  하늘 배경                     — 정적
```

차선은 별도 레이어지만 아스팔트와 **동일한 속도 변수**로 묶어 항상 동기화된다. 아스팔트 타일에는 차선을 포함하지 않아도 되므로 순수 노면 질감만 그리면 된다.

---

### 아스팔트 타일 규격 및 배리에이션

타일은 **가장 가까운 위치(z=1.0) 기준**으로 한 장만 제작한다. 코드가 z값에 따라 세로 높이를 자동 축소한다. 가로는 항상 320px 유지.

| 타일 | 규격 (원본) | 내용 |
|------|-----------|------|
| A — 기본 | 1280×16px | 단색 어두운 아스팔트 #2A2420 |
| B — 반사 | 1280×16px | 약간 밝은 줄. 헤드라이트 원뿔 안쪽 구간 |
| C — 균열 | 1280×16px | 불규칙 밝은 픽셀 1~2개. 낡은 노면 질감 |
| D — 습기 | 1280×16px | 파란빛 섞인 회색. 비 오는 구간 |
| E — 오일 | 1280×16px | 어두운 갈색 패치. 폐차·사고 지점 근처 |

z값에 따른 세로 축소 예시:

```
z=1.0 (화면 하단, 가장 가까움) → 높이 16px 원본 그대로
z=0.7 (중간)                   → 높이 약 11px 로 축소
z=0.4 (먼 거리)                → 높이 약 6px 로 축소
z=0.1 (소실점 근처)            → 높이 2px 로 축소
```

픽셀 뭉개짐 방지를 위해 텍스처 필터는 반드시 **Nearest Neighbor** 적용.

### 차선 구성

한국 2차로 국도 기준. 고증보다 게임플레이 가독성·속도감 우선.

| 차선 종류 | 색상 | 패턴 | 이유 |
|---------|------|------|------|
| 중앙선 | 황색 | 점선 | 점선 스크롤이 속도감을 직관적으로 전달 |
| 갓길선 | 흰색 | 실선 | 도로 경계 명확히 구분 |

```
│  ← 흰색 실선 (갓길)
│
  ─  ─  ─  ← 황색 점선 (중앙, 스크롤로 속도감 생성)
│
│  ← 흰색 실선 (갓길)
```

### 커브 구현

별도 이미지 불필요. 도로 전체에 x축 오프셋을 적용해 코드로만 처리.

```gdscript
# curve_value: 양수=우회전, 음수=좌회전
# z값을 곱해 소실점 근처는 적게, 화면 하단은 많이 이동
func apply_curve(x_pos: float, z_value: float, curve_value: float) -> float:
    return x_pos + curve_value * z_value

# 아스팔트·차선·오브젝트 레이어 모두 동일한 curve_value 적용
```

아스팔트, 차선, 오브젝트 레이어 전부 같은 커브값을 받으므로 모든 요소가 자연스럽게 같이 휘어진다.

---

### 언덕 구현

커브와 동일한 원리. 커브는 소실점을 x축으로 이동시키고, 언덕은 소실점을 **y축으로 이동**시킨다. 별도 이미지 불필요. 코드로만 처리.

```
평지:   소실점 y = HORIZON_Y (고정)
오르막: 소실점 y = HORIZON_Y - hill_value (위로 이동)
내리막: 소실점 y = HORIZON_Y + hill_value (아래로 이동)
```

커브와 언덕을 동시에 적용하면 굽어 올라가는 산길도 표현 가능하다.

```gdscript
# 커브 + 언덕 동시 적용
# hill_value: 양수=내리막, 음수=오르막
func get_horizon_pos(curve_value: float, hill_value: float) -> Vector2:
    return Vector2(
        SCREEN_CENTER_X + curve_value,
        HORIZON_Y + hill_value
    )

# 모든 도로 레이어의 소실점을 이 값으로 갱신
```

### 구간별 언덕 설계

| 구간 | 지형 | hill_value | 연출 목적 |
|------|------|-----------|---------|
| 1구간 | 평지 | 0 | 튜토리얼. 단순한 조작 익힘 |
| 2구간 | 완만한 오르막 | -30~-60 | 지평선 너머 컬트 무리 늦게 등장 |
| 3구간 | 굽은 내리막 | +40~+80 | 커브와 조합. 헤드라이트 너머 안 보임 |
| 4구간 | 평지 → 급내리막 | 0 → +120 | 사슴머리가 내리막 끝에서 갑자기 등장 |

### 내리막 공포 연출

내리막 구간에서 도로가 아래로 꺾이면 헤드라이트 범위 너머가 보이지 않는다. 언덕 너머에 컬트·사슴머리를 배치하면 헤드라이트에 갑자기 등장하는 점프스케어 구조가 된다.

```
[내리막 진입 중]        [내리막 끝 도달 순간]
━━━━━━━              ━━━━━━━━━━━
     ↘                          ████  ← 갑자기 등장
      (아무것도 안 보임)
```

### 원경 시차 스크롤 (Parallax Scrolling)

커브·언덕에서 원경이 거리에 비례해 다르게 반응한다. 가까운 오브젝트는 빠르게 이동하고 먼 배경은 거의 움직이지 않는 시차 효과. OutRun이 코너에서 원경이 좌우로 스크롤되는 것과 동일한 원리다.

**레이어별 커브 반응 속도**

| 레이어 | 커브 반응 계수 | 언덕 반응 계수 | 비고 |
|--------|------------|------------|------|
| 나무·전봇대 (갓길) | 1.0 | 1.0 | 도로와 동일 |
| 산 실루엣 | 0.3 | 0.3 | 멀리 있는 산능선 |
| 구름 | 0.1 | 0.05 | 거의 안 움직임 |
| 하늘 베이스 | 0.0 | 0.0 | 완전 정적 |

**구현 방식**

Godot 내장 `ParallaxBackground` + `ParallaxLayer` 노드를 사용한다. 커브값과 언덕값을 매 프레임 누적해서 각 레이어 오프셋에 반영한다.

```gdscript
# 매 프레임 호출
func update_parallax(curve_value: float, hill_value: float):
    parallax_x += curve_value

    # 레이어별 반응 계수 적용
    mountain_layer.motion_offset.x = -parallax_x * 0.3
    mountain_layer.motion_offset.y = -hill_value  * 0.3
    cloud_layer.motion_offset.x    = -parallax_x * 0.1
    cloud_layer.motion_offset.y    = -hill_value  * 0.05
    # 하늘 레이어는 고정
```

### 원경 리소스 규격

원경은 좌우 스크롤 시 경계가 보이면 안 되므로 **가로 심리스(seamless)** 이미지로 제작한다.

| 레이어 | 내용 | 규격 | 비고 |
|--------|------|------|------|
| 산 실루엣 | 야간 산·숲 능선 어두운 실루엣 | 2560×180px | 화면 가로 2배. 심리스 |
| 구름 | 야간 구름 실루엣 | 2560×120px | 심리스 |
| 하늘 베이스 | 단색 or 상하 그라디언트 | 1280×720px | 정적. 타일링 불필요 |

산 실루엣 하나만 있어도 원경 느낌은 충분히 난다. 구름은 선택 사항.

### 전봇대 배치 시스템

전봇대는 구간 내 **일정 간격**으로 배치된다. 간격이 균일하면 화면에 동시 존재하는 전봇대 수가 예측 가능해져 전깃줄 계산 비용이 최소화된다. 전봇대 간격이 일정하면 지나치는 리듬이 속도감 지표 역할도 한다.

**배치 규칙**

| 항목 | 값 | 비고 |
|------|-----|------|
| 기본 간격 | 40m | 실제 한국 국도 전봇대 간격 근사 |
| 화면 동시 존재 수 | 최대 2~3개 | 오브젝트 풀로 관리 |
| 전깃줄 연결 | 인접한 두 전봇대 사이에만 | 화면 밖 전봇대와는 연결 안 함 |
| 구간별 간격 변화 | 후반 구간일수록 간격 넓어짐 | 황폐함 연출 |

**구간별 간격**

| 구간 | 전봇대 간격 | 분위기 |
|------|-----------|--------|
| 1구간 | 40m | 일반 국도 |
| 2구간 | 40m | 일반 국도 |
| 3구간 | 60m | 관리 소홀 느낌 |
| 4구간 | 80m | 황폐. 전깃줄 처짐이 크게 보임 |

**전깃줄 동적 생성**

전깃줄은 이미지가 아니라 매 프레임 코드로 그린다. 두 전봇대의 현재 화면 좌표를 계산해 베지어 곡선으로 연결한다.

```gdscript
# 인접 전봇대 두 개의 화면 좌표를 받아 전깃줄을 그림
# 720p 네이티브에서 픽셀아트 느낌 유지를 위해 width=2, antialiased=false
func draw_wire(pole_a: Vector2, pole_b: Vector2, sag: float):
    var mid = Vector2(
        (pole_a.x + pole_b.x) / 2,
        max(pole_a.y, pole_b.y) + sag
    )
    # 베지어 곡선을 폴리라인으로 근사
    var points = get_quadratic_bezier_points(pole_a, mid, pole_b, 12)
    draw_polyline(points, WIRE_COLOR, 2.0, false)
    #                                  ↑     ↑
    #                            2px 선폭  antialiased=false
```

전봇대 간격이 넓을수록 `sag` 값을 크게 주면 처짐이 깊어진다. 별도 이미지 제작 없음.
